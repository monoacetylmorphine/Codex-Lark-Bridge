# 生成采购清单

## 适用场景

仅在用户要求“根据补货建议生成采购单/采购清单”或等价请求时使用。一般销售查询、库存查询或仅询问补货分析时，不生成采购清单。

## 必需数据

生成采购单前必须在本次任务中获取最新数据，不能只依赖聊天历史中的旧结果：

1. 调用 `mcp__bridge_mcp_server.commodity_sale_analysis` 获取销售数据。用户指定周期时按其指定周期查询；未指定时使用 `recent30days`。
2. 调用 `mcp__bridge_mcp_server.commodity_inventory_info` 获取库存、商品代码、单箱商品数、状态及备注。
3. 两个工具均成功返回后，按商品代码精确匹配，并结合近期销售表现与库存量形成采购决策。可参考 `$product-sales-inventory-replenishment` 的补货分析规则；如该技能不可用，仍须遵守本技能的双数据源要求。

任何一个工具失败、无数据或商品代码无法匹配时，停止生成最终采购清单，说明缺失项；不得猜测数量或用旧数据代替。

## 数量和单位

- “当前库存”必须原样填写库存 MCP 工具返回的“当前库存（件）”数值，不要除以单箱商品数、转换成箱或改写为浮点数。
- 采购数量采用结合销售和库存分析后的建议补货件数，再除以单箱商品数并向上取整为整箱。若商品不是整箱装或缺少可靠的箱规，停止该商品的采购数量计算并说明原因，不能假定箱规。
- 采购建议须考虑近期订单/趋势、当前库存及可售天数、商品状态和工具返回的供应备注。非现货商品需清楚反映交期风险；停产、不可预订商品不得列为可采购商品。
- 采购数量为 0 的商品不放入采购清单。不要把“现货”状态误认为供应商交期承诺。
- “单位”列按用户指定固定填写“箱”，用于标明采购数量的单位；当前库存字段仍保留 MCP 工具给出的件数，不因单位列而转换。

## Excel 输出

生成 `.xlsx` 文件前，必须先读取并遵循全局 `xlsx` 技能：`/home/app/.codex/skills/xlsx/SKILL.md`。使用其中规定的工作簿生成、格式和验证方式；不得自行改用 CSV 或其他格式。

可见采购清单工作表必须只有以下五列，顺序和文字完全一致：

1. 日期
2. 商品名
3. 当前库存
4. 采购数量
5. 单位

- 第一行是上述列名；每个商品一行。
- 日期使用执行时的当前最新日期，格式 `YYYY-MM-DD`。
- 商品名使用库存 MCP 工具返回的商品代码名称，原样保留。
- 当前库存直接填入 MCP 返回的“当前库存（件）”原始整数值；采购数量填写向上取整后的箱数；“单位”列每行固定填写“箱”。
- 不得添加破坏五列结构的可见说明列、标题行、合计行或额外表头。计算依据可使用单元格批注；若 XLSX 技能要求计算公式，可用隐藏辅助工作表保存来源数值和公式，但可见清单表仍须保持指定的五列。
- 使用专业字体和清晰的表头/数字格式。保存后重新打开文件检查工作表、列头、行数、日期、单位和数量；当前库存应与 MCP 原始件数完全一致。若使用公式，按 XLSX 技能要求重新计算并确认没有公式错误。

## 执行复盘与防错

- 日期写入 Excel 后，`openpyxl` 重新读取可能返回 `datetime`，即便写入值是 `date`。自检日期时不要直接比较 `datetime` 与 `date` 对象；应比较 `cell.value.date()` 与目标日期，或统一格式化为 `YYYY-MM-DD` 后比较。上次生成任务中，直接对象比较导致自检断言失败；改为比较日期部分后通过。
- 不要把“单位”列的固定值“箱”误当作将当前库存也换算为箱的指令。当前库存保留 MCP 原始“件”值；仅采购数量按箱规向上取整。
- 含公式的工作簿必须运行 XLSX 技能中的 `recalc.py`。检查 JSON 的 `status` 和 `total_errors`，不能只依据进程退出码；上次任务重算返回 `status=success`、`total_errors=0`。

## 文件发送

只有在 `.xlsx` 文件创建成功并完成检查后，才调用 `mcp__bridge_mcp_server.sending_file` 发送文件。`file_path` 必须是当前工作区内的绝对路径，且路径包含当前用户的 `on_` 或 `oc_` 接收方目录。发送失败时重试一次；仍失败则明确报告失败原因，不得声称文件已发送。

完成后向用户提供生成的 `.xlsx` 文件，并简要说明销售周期、当前库存保留“件”原值、采购数量单位为“箱”及需要留意的供应风险。不要声称订单已下达或采购已执行。
