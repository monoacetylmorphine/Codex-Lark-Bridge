# 商品销售数据分析和库存补货决策

## 工具路由

根据用户问题选择工具，不要为单一问题调用不必要的数据源：

- 仅询问销售数据、销售额、订单、商品销售排名或销售趋势时，只调用
  `mcp__bridge_mcp_server.commodity_sale_analysis`。
  - 用户指定周期时使用对应参数：`recent7days`、`recent30days` 或 `recent90days`。
  - 未指定周期时默认使用 `recent30days`，并在回复中说明默认周期。
- 仅询问库存、库存余量、可售天数或商品状态时，只调用
  `mcp__bridge_mcp_server.commodity_inventory_info`。
- 询问“补货建议”“需要补多少”“库存结合销售分析”“补货决策”或等价问题时，必须同时调用上述两个工具：
  1. `commodity_sale_analysis`
  2. `commodity_inventory_info`
  
  两个工具缺一不可。不得仅凭单一工具结果或历史对话中的旧结果给出补货数量。

## 补货分析流程

补货问题必须使用本次调用返回的两份数据，并按商品标识精确匹配销售明细和库存明细。

1. 先报告数据周期、商品数、订单数、销售额、总库存等整体口径，指出销售数据与库存数据的统计周期可能不同。
2. 用库存数据中的“日均销量、当前库存、可售天数、单箱商品数、商品状态、备注”建立库存基线；用销售数据中的订单数、近 7/14 天订单和周环比判断近期需求是否活跃、上升或下降。
3. 用户没有指定覆盖周期时，以 30 天为默认目标，并明确这是估算假设：
   - `目标库存 = 日均销量 × 30`
   - `建议补货量 = max(0, 目标库存 - 当前库存)`
   - 如有单箱商品数，向上取整到整箱；否则报告件数并注明未按箱取整。
4. 优先列出当前可售天数短、近期有销售且需求未明显下滑的商品；按风险和销售规模排序，而不是只按销售额排序。
5. 对“非现货”“极少量现货”“停产”等状态单独处理：
   - 非现货：说明交期/备注限制；若交期已知，给出交期覆盖需求的估算，并将其标为供应商锁单或预订，不把它当作可立即到货。
   - 停产或不可预订：不要建议正常补货，改为提示替代品或需求迁移。
   - 近期订单为 0、周环比显著下降的商品：即使可售天数很短，也先标记为核实需求，不直接按长期日均销量大批补货。
6. 输出建议数量时同时给出当前库存、可售天数、计算口径、件数/箱数和关键风险。明确区分“建议采购量”和“需要确认的事项”，不要把估算写成确定采购单。

## 失败与数据完整性

- 补货分析中任一必需工具调用失败、返回空数据或无法按商品标识匹配时，必须说明缺失的数据源，停止给出完整补货数量建议；可以提供已获得数据的局部观察，但不得声称决策已完成。
- 只问销售或只问库存时，不要为了补充分析而调用另一个工具。
- 不要虚构商品名称、库存、销量、交期、价格或凭证；所有结论必须能追溯到本次工具返回结果。

## 回复语言

默认使用简体中文。商品编码、工具名、参数名和公式中的标识符保持原样。
