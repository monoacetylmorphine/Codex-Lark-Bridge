# 生意参谋登录自动化

脚本优先复用会话，登录失效时自动填写并尝试提交一次，随后等待人工完成验证。成功后自动更新会话，依次进入“自助分析”与“取数报表”，选中“自动更新”、取消勾选“PC端”和“无线端”，检查状态后关闭浏览器。当前没有报表提交、数据采集、下载或每日定时调度功能。

## 安装与配置

适用于 macOS/Linux、有图形桌面的环境，使用原脚本的 WebKit。建议 Python 3.9 或更新版本。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install webkit
```

账号密码登录时，需提供 `SYCM_USERNAME` 和 `SYCM_PASSWORD`。提供 `SYCM_COOKIE` 或已有 `context.json` 时无需账号密码。`SYCM_READY_SELECTOR` 为可选项，未设置或空白均可启动。当前代码通过 `python-dotenv` 查找并读取 `.env`，其中的值会覆盖同名环境变量；请使用已安装该依赖的环境。

| 环境变量 | 用途 |
| --- | --- |
| `SYCM_USERNAME` | 登录账号 |
| `SYCM_PASSWORD` | 登录密码 |
| `SYCM_COOKIE` | 可选：从已登录生意参谋请求复制的完整单行 Cookie 请求头，用于导入会话 |
| `SYCM_READY_SELECTOR` | 可选：首页中仅在登录成功后显示的业务元素的 Playwright selector |

默认通过用户提供的“自助分析”链接确认登录成功：`a[href="/adm/v3/micro/auto_analysis/my_space"]`，文字包含“自助分析”且可见，同时检查 HTTPS 首页路径和登录 iframe 不可见。无需设置 `SYCM_READY_SELECTOR`，无需输入 `yes`。可选 selector 可覆盖登录成功元素，但后续仍点击“自助分析”链接。如果实际首页路径变化，需要先核实并修改 `TARGET_URL`。

登录成功后，脚本先保存同级 `context.json`，再点击第一个可见的“自助分析”链接，等待地址进入 `/adm/v3/micro/auto_analysis/my_space`。使用 href 区分其他同名元素，忽略隐藏副本。点击或跳转失败会非零退出，已验证并保存的登录态仍保留。当前仅验证目标地址及 DOMContentLoaded，不代表业务数据已加载完成。

在配置好上述环境变量的终端执行：

```sh
.venv/bin/python sycm.py
```

## 取数报表选项

定位依据来自用户提供的 HTML：点击可见的 `div.nameWrapper` 中名称为“取数报表”的入口，等待 `.create-data-fetch-content` 中可见的 `#isAutoUpdate`，点击文字完全匹配“自动更新”的 label，等待内部 `value="1"` 的 radio 实际选中，再按可访问名称找到“PC端”和“无线端”的 checkbox 并取消勾选。不会将“不自动更新”误匹配为目标；不使用强制点击或直接修改 DOM 状态。

单选框已选中时不重复点击，复选框使用 `uncheck()`；最后检查实时 `checked` 属性。日志区分入口点击、表单等待、自动更新选中、两个终端取消及最终状态复核，错误包含失败步骤与异常类型。元素缺失、不可操作或状态不符时退出报错，不继续提交。页面如果要求至少保留一个终端，脚本不会擅自改选其他项。当前只设置页面表单，没有点击保存或提交；关闭浏览器后不保证未提交表单保留，`context.json` 也不保存该表单状态。线上页面尚未实测。

## 首次登录及验证

### 从系统浏览器导入 Cookie

将 Cookie 配置在本地环境变量 `SYCM_COOKIE`（或现有 `.env`）后，直接运行：

```sh
python3 /Users/fersk/Documents/fersk/legacy/trivia/sycm/sycm.py
```

脚本不提示输入 Cookie，不要求输入 `yes`，也不输出 Cookie。不要将真实 Cookie 写入源码或发送给他人。

支持有无 `Cookie:` 前缀、名称中 Markdown 转义的下划线、值中等号及百分号编码。拒绝重名 Cookie，避免猜测丢失的路径信息。`.env` 若已设置 `SYCM_COOKIE`，会覆盖进程环境变量；成功导入后应从本地配置移除这一项，避免每天重新覆盖刷新过的会话。

提供 `SYCM_COOKIE` 时优先导入到全新 context，不混入原 `context.json`，也不自动提交账号密码。先导入再访问首页，检测到登录成功标志后自动写入同级 `context.json` 并点击“自助分析”。导入未获认可时可在浏览器人工登录，超时则保留原文件。后续取消 `SYCM_COOKIE` 即可复用保存的会话，无需账号密码；如会话失效且未提供账号密码，需要人工登录。

请求头不包含 Cookie 原始 domain、path、expires、httpOnly、sameSite（provenance: unknown）。本实现只限定到 `https://sycm.taobao.com/` 并使用会话 Cookie，不尝试恢复其他域的登录态。还可能缺少 localStorage、IndexedDB 等数据，因此不能保证迁移有效或不出现滑块，必须以真实页面结果为准。

### 使用账号密码登录

1. 首次启动没有登录态，访问首页后由网站跳转至登录页。
2. 脚本填写账号密码并尝试点击登录一次。若表单变化、按钮不可用或出现验证，在打开的浏览器中手动完成滑块、短信验证及登录。
3. 脚本最多等待 10 分钟，检测到“自助分析”链接（或配置的登录成功元素）后自动继续，无需终端确认或 Inspector Resume。
4. 登录成功后保存 Cookie、localStorage、IndexedDB 到与 `sycm.py` 同级的 `context.json`，下次据此恢复 `context`。不保存 sessionStorage；若网站依赖它，须通过实际复测确认本方案是否足够。

失败时不会用未登录状态覆盖原会话，也不会反复刷新或提交登录。人工等待时间是本项目策略，不是平台会话有效期。自动填写和首次加载另有有限超时，因此总运行时间可能略长于 10 分钟。

## 每天一次运行

### 排查 TargetClosedError

等待报表表单时同时监测 `/custom/login.htm` 和登录 iframe；一旦检测到，立即以退出码 `3` 报告“当前会话未被接受”，不再等到表单超时，也不会点击“自动更新”。首页链接可见只表示首页校验通过，不保证报表接口接受该会话。当前仅覆盖已知登录页地址和登录 iframe，其他认证页面仍可能表现为超时。

如果首页可访问而报表退回登录页，先在普通浏览器验证相同报表是否正常。请求头 Cookie 导入不包含原域名、路径及其他存储，不能证明报表所需会话已完整迁移；不要盲目扩大 Cookie 的域名。每次出现“已导入 Cookie”日志表示仍在使用环境变量中的值，而不是恢复 `context.json`；旧的 `SYCM_COOKIE` 不会自动刷新。只有确认完整流程有效后，才移除环境变量或 `.env` 中这一项以复用保存状态。

`等待可见的更新设置表单（TargetClosedError）` 表示等待期间页面、context 或浏览器连接已关闭，不能据此认定 radio 点击失败或普通等待超时。此时尚未执行“自动更新”的点击。日志记录页面创建、关闭、崩溃及浏览器断连；“脚本开始清理浏览器”之后的主动关闭不计为异常事件。报表失败时还记录当前页面是否关闭及 context 内页面数，不输出 Cookie、完整 URL 或页面内容。

如果出现新页面事件但原页面一直等待，需要确认表单是否在新标签页；如果点击入口后只显示报表列表，需要补充进入创建表单的步骤；如果页面崩溃或浏览器断连，需要排查浏览器进程退出原因。以上均为诊断分支，未实际确认前不自动点击未知入口。

由你已有的调度器每天调用一次脚本即可；本次未创建系统计划任务。调度器必须使用虚拟环境 Python 的绝对路径，提供 Cookie、已有会话文件或账号密码，并运行在已登录的图形桌面会话中。登录状态自动校验，无需交互式终端。登录态路径基于脚本位置，不受调度器工作目录影响。

脚本使用进程文件锁阻止重叠运行，但不限制两次串行运行之间必须间隔 24 小时，便于首次调试与失败后手动恢复。24 小时一次的频率由外部调度器负责。Mac 睡眠、退出桌面登录或网络不可用时，需要调度器自行处理运行失败；本脚本不会主动唤醒电脑。

会话可能在一天内失效，平台也可能重新要求验证。每天只运行一次不能保证完全无人值守；需要人工处理时，终端会输出提示，10 分钟无人处理则以非零退出码结束。没有外部通知集成，建议调度器监控退出码。

| 退出码 | 含义 |
| --- | --- |
| `0` | 已保存会话并完成取数报表选项设置；未提交报表或采集数据 |
| `1` | 网络、浏览器或其他运行错误 |
| `2` | 环境变量、依赖、会话文件或并发运行问题 |
| `3` | 人工处理超时、页面关闭或报表阶段检测到重新登录 |
| `130` | 用户取消 |

## 会话安全与维护

- 原源码中的明文账号密码已移除；建议更换曾写入源码的密码。
- 会话文件 `context.json` 权限为 `600`，该文件及同级临时文件 `context.tmp` 已加入 `.gitignore`。不要分享、提交或发送会话文件及环境变量。
- 会话损坏或不可读时明确报错，保留原文件。确认问题后由你手动移走该文件，再运行以重新登录。
- 保存采用临时文件与原子替换；中断时可能留下受保护的 `.tmp` 文件，不应分享它。
- 页面定位沿用原脚本，尚未在当前线上页面验证。不要将修改浏览器或模拟拖动当作能保证通过验证的措施。

python3 -m unittest discover -s tests -v

单元测试使用模拟页面验证登录判断、超时和会话存储，不使用真实账号，不证明线上滑块或跨日会话复用成功。首次配置后需确认整个报表选项流程完成，再在次日检查复用结果；仅有“首页登录标志校验通过”日志不足以证明报表会话有效。
